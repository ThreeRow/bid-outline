# 文本流程提示词

0.13.1根据用户审阅意见修订，模板版本`self-contained-prompts-1`。这是已应用的审阅稿，尚未用真实模型验证效果；后续可继续调整。所有14份模板以角色、背景、输入说明、任务及返回内容组织。

`model/text_tasks.py::render`在`{context}`处填入程序提供的本次章节、自然语言目标和必要共同条件；任务说明后以`---`分隔原始资料。只渲染一条完整user消息，train单条和批量query均原样使用该文本，预算也使用同一序列化。P任务仍保留原有system/user拼接方式。

| 任务 | 输入 | 输出 |
|---|---|---|
| E01 | 章节目录 | 先定义三类内容，再用A/B/C标记真实章节路径 |
| E00 | 目标内容、所属章节、命中线索、局部上下文 | 保留/排除/待核首行及可选简短说明 |
| N01-A | 格式编制相关原文 | 直接生成技术部分目录草稿 |
| N01-B | 评审相关原文 | 沿用原句整理技术评审要求 |
| N01-C | 技术需求和响应相关原文 | 沿用原句整理约束、指标、范围和材料要求 |
| E02 | 自然语言目标、位置、完整块 | 起始句/结束句/中间锚点，供Python回取原文 |
| E03-A | A目录草稿 | 合并后的A目录 |
| E03-B/C | 同类原文顺序块结果 | 整理后的要求文本 |
| N02-A | A锚点回取的原文 | 转为目录；只在锚定A路径调用，direct默认不重复调用 |
| N02-B | B整理结果 | 显式展开列项及评价维度的目录 |
| N03 | 标明真实角色的格式目录/评审目录/累计草稿 | 完整融合目录 |
| N04 | 目录与技术要求/响应项 | 补充后的完整目录 |
| N05 | 最后草稿 | 统一表达和层级的最终目录 |

单类模板不要求模型先理解A/B/C字母。模板只说明本次产物，去除“不生成目录、不输出代码”等范围外说明。N02-B不再使用范本适配、工具提供等固定项目示例，评价维度按输入实际出现的内容展开。

目录输出只用缩进表达层级，不加Markdown标记或章节编号。程序未新增逐节点目录解析，机械采用成功不代表内容正确。

E00保留三态。其他任务无相关内容统一整答“无”；执行器仅对去除首尾空白后恰好为“无”的回答记录no_content。原始回答仍保存，空答/失败不作无内容；包含“无”字的正文按正常内容处理。无内容的块和汇总不再进入下游生成。已有草稿时融合/补充/润色突然回答“无”，保留原草稿并记录未处理。

章节和反馈位于分隔线前，原始正文位于分隔线后。匹配澄清、锚点修正保持原文不变。A原文经E02回取后，先由N02-A生成目录，再由E03-A合并；B/C锚点文本交对应汇总。没有新增复杂业务字段、来源ID或JSON输出要求。

阈值感知仍待下一步实现。本轮没有改变text_batch_tokens=3000、已有分块和固定汇总策略，也没有增加9000/4000配置。模板、序列化和流程版本变化需新运行目录，旧run只读导出继续保留。
